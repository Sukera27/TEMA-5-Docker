Tema 5

Docker: imágenes, contenedores y Compose

Qué es Docker y cómo se usa para desplegar una aplicación: una práctica en local con una API Spring Boot (simpsons) y MySQL, primero con un Dockerfile y arrancando los contenedores a mano, y después con docker-compose para levantar API y base de datos con un solo comando.

1¿Qué es Docker?

Docker es una plataforma para empaquetar una aplicación con todo lo que necesita (el runtime, las librerías, la configuración) y ejecutarla de forma aislada en cualquier máquina. Soluciona el clásico "en mi ordenador funciona": lo que funciona dentro del paquete funciona igual en el portátil del alumno, en un servidor o en Azure.

3Entorno de trabajo y proyecto

Esta sesión se hace en local, en tu ordenador (la siguiente se llevará a Azure). Necesitas Docker Desktop abierto y en marcha, y Java 17 para compilar el proyecto (usaremos el ./mvnw que ya trae, no hace falta instalar Maven). Para la práctica 1 usaremos el MySQL instalado en tu equipo (puerto 3306); en la práctica 2 lo pondrá Docker.

1

Comprobar que Docker funciona

docker --version
docker compose version
docker run hello-world

El último comando descarga una imagen mínima y la ejecuta: si imprime "Hello from Docker!", todo está bien. Si dice Cannot connect to the Docker daemon, Docker Desktop no está abierto.

2

Abrir una terminal en la carpeta del proyecto

cd simpsons
ls

Debes ver pom.xml, src/ y los ficheros de Docker: Dockerfile, docker-compose.yml y .env.example.

La API de ejemplo: simpsons

Es una API Spring Boot 3.5 (Java 17) con una sola tabla, simpsons, en MySQL. Escucha en el puerto 8080 y tiene dos endpoints:

MétodoRutaQué hace
GET/api/v1/simpsonLista los registros (el último primero)
POST/api/v1/simpsonGuarda uno nuevo ({"name": "...", "picUrl": "..."})
Cómo se conecta la API a la base de datos (y por qué no hay que tocar su código) Su application.yaml apunta a jdbc:mysql://localhost:3306/simpsonsaudit con usuario y contraseña fijos. Dentro de un contenedor, localhost es el propio contenedor, así que ahí no hay MySQL. Spring permite pisar cualquier propiedad con una variable de entorno: SPRING_DATASOURCE_URL sustituye a spring.datasource.url, y lo mismo con SPRING_DATASOURCE_USERNAME y SPRING_DATASOURCE_PASSWORD. Además tiene ddl-auto: update, así que Hibernate crea la tabla solo y no hace falta ningún script SQL.

4Práctica 1: Dockerfile y contenedores a mano

Primero solo con el Dockerfile: construimos la imagen de la API, arrancamos su contenedor y la conectamos al MySQL de tu equipo. Después, con Docker Compose, pondremos también la base de datos en un contenedor.

1

Compilar el .jar

./mvnw clean package -DskipTests
ls target/*.jar

Genera target/simpsons-0.0.1-SNAPSHOT.jar, el programa ya empaquetado. -DskipTests evita ejecutar el test de Spring, que necesita una base de datos MySQL arrancada y todavía no la tenemos.

2

El Dockerfile

Está en la raíz del proyecto. Es corto: parte de una imagen con Java, copia el .jar y lo ejecuta.

FROM eclipse-temurin:17-jre

WORKDIR /app
COPY target/*.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
InstrucciónQué hace
FROMImagen base sobre la que se construye. 17-jre lleva solo el Java necesario para ejecutar (no compilar)
WORKDIRCarpeta de trabajo dentro de la imagen
COPYCopia el .jar del equipo a la imagen, con el nombre app.jar
EXPOSEDocumenta el puerto de la aplicación (no lo publica: eso lo hace -p)
ENTRYPOINTComando que se ejecuta al arrancar el contenedor

Junto al Dockerfile hay un .dockerignore (como un .gitignore): dice qué no se envía a Docker al construir. Entre otras cosas deja fuera .env, para que los secretos nunca acaben dentro de una imagen.

3

Construir la imagen

docker build -t simpsons-api:1.0 .
docker images

-t le pone nombre y etiqueta a la imagen; el punto final es el contexto (la carpeta cuyos archivos puede copiar COPY). En docker images debe aparecer simpsons-api con la etiqueta 1.0.

4

Preparar la base de datos local

En esta práctica la API se ejecuta en un contenedor, pero la base de datos es el MySQL instalado en tu equipo, que debe estar arrancado (puerto 3306). Solo hace falta que exista la base de datos; las tablas las crea la propia API al arrancar (ddl-auto: update):

mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS simpsonsaudit;"

Si no tienes el cliente mysql en la terminal, crea la base de datos simpsonsaudit desde MySQL Workbench.

5

Arrancar el contenedor de la API

docker run -d --name simpsons-api -p 8080:8080 \
  -e SPRING_DATASOURCE_URL="jdbc:mysql://host.docker.internal:3306/simpsonsaudit?useSSL=false&allowPublicKeyRetrieval=true" \
  simpsons-api:1.0
  • -d lo ejecuta en segundo plano y --name le da nombre.
  • -p 8080:8080 publica el puerto: lo que llegue al 8080 de tu equipo va al 8080 del contenedor.
  • Dentro del contenedor, localhost es el propio contenedor, no tu equipo, y ahí no hay MySQL. Para llegar al MySQL de tu equipo se usa el nombre especial host.docker.internal, que Docker Desktop resuelve como "la máquina anfitriona" (en Linux hay que añadir --add-host=host.docker.internal:host-gateway).
  • El usuario y la contraseña son los del application.yaml (root / root). Si tu MySQL local tiene otra contraseña, añade -e SPRING_DATASOURCE_USERNAME=... y -e SPRING_DATASOURCE_PASSWORD=....
6

Ver el arranque y probar la API

docker logs -f simpsons-api

Cuando aparezca Started SimpsonsApplication, sal del log con Ctrl+C (el contenedor sigue funcionando) y prueba:

curl http://localhost:8080/api/v1/simpson

curl -X POST http://localhost:8080/api/v1/simpson \
  -H "Content-Type: application/json" \
  -d '{"name":"Homer Simpson","picUrl":"https://example.com/homer.png"}'

curl http://localhost:8080/api/v1/simpson

Después del POST, el segundo GET devuelve a Homer. El dato está en tu MySQL local, no dentro del contenedor, y puedes verlo con:

mysql -uroot -p simpsonsaudit -e "SELECT * FROM simpsons;"
7

Gestionar el contenedor y limpiar

docker ps                  # en ejecución
docker stop simpsons-api   # parar
docker start simpsons-api  # volver a arrancar

# Limpiar antes de la práctica 2:
docker rm -f simpsons-api

Borrar el contenedor no borra los datos: siguen en tu MySQL. Limpiar es necesario porque la práctica 2 usa el mismo nombre de contenedor y el mismo puerto 8080.

Si la API se cae al arrancar Mira el motivo con docker logs simpsons-api. Communications link failure o Connection refused: MySQL no está arrancado en tu equipo, o la URL usa localhost en vez de host.docker.internal. Access denied: usuario o contraseña distintos de root / root. Unknown database: falta crear simpsonsaudit (paso 4). Si MySQL rechaza al usuario root por venir "desde otra máquina" (Host ... is not allowed to connect), crea un usuario que acepte cualquier origen y pásalo con -e: 
CREATE USER 'docker'@'%' IDENTIFIED BY 'docker1234';
GRANT ALL ON simpsonsaudit.* TO 'docker'@'%';
Qué hemos conseguido y qué falta La API ya va dentro de un contenedor, empaquetada con su Java y lista para llevarla a cualquier sitio, pero la base de datos sigue fuera, en tu equipo. En la práctica 2 pondremos también MySQL en un contenedor y Docker Compose se encargará de levantar y conectar los dos.

5Práctica 2: docker-compose

Docker Compose describe en un único fichero YAML todos los contenedores de la aplicación y cómo se relacionan. Con docker compose up se crea la red y los dos contenedores, y con docker compose down se retira todo.

5.1 El archivo .env

Compose lee automáticamente el archivo .env de la carpeta del proyecto. Ahí van los datos de la base de datos, para no escribirlos en el docker-compose.yml. Se crea copiando el de ejemplo:

cp .env.example .env

Y su contenido es:

DB_USERNAME=simpsons
DB_PASSWORD=cambia_esta_clave
DB_NAME=simpsonsaudit

Cambia la contraseña por la tuya. DB_USERNAME no puede ser root, porque MySQL reserva ese usuario y no deja crearlo con esta variable.

5.2 El docker-compose.yml

services:

  db:
    image: mysql:8.4
    container_name: simpsons-db
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: ${DB_NAME}
      MYSQL_USER: ${DB_USERNAME}
      MYSQL_PASSWORD: ${DB_PASSWORD}
    ports:
      - "3307:3306"

  api:
    build: .
    container_name: simpsons-api
    restart: unless-stopped
    depends_on:
      - db
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://db:3306/${DB_NAME}?useSSL=false&allowPublicKeyRetrieval=true
      SPRING_DATASOURCE_USERNAME: ${DB_USERNAME}
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD}
ClaveQué hace
servicesLista de contenedores: db y api. Compose crea una red y cada servicio se encuentra por su nombre (por eso la URL usa db)
image / buildUsar una imagen ya hecha (mysql:8.4) / construirla con el Dockerfile de esta carpeta (.)
container_nameNombre fijo del contenedor (si no, Compose inventa uno)
restartunless-stopped: el contenedor se reinicia solo si se cae, salvo que lo pares tú
environmentVariables de entorno del contenedor (equivale a los -e). ${DB_PASSWORD} se rellena con el valor del .env
portsPuertos publicados (equivale a -p). El 3307:3306 permite conectar desde Workbench u otro cliente al MySQL del contenedor sin chocar con un MySQL local en el 3306
depends_onOrden de arranque: la API se arranca después del contenedor de MySQL
¿Y si la API arranca antes de que MySQL esté listo? depends_on solo espera a que el contenedor de MySQL arranque, no a que la base de datos esté lista (tarda unos 20-30 segundos). Por eso la API puede fallar al principio con Communications link failure. No pasa nada: gracias a restart: unless-stopped Docker la reinicia sola hasta que MySQL responde. Es normal verla en estado Restarting un par de veces.

5.3 Levantar la aplicación

1

Construir y arrancar todo

docker compose up -d --build

--build construye la imagen de la API con el Dockerfile y -d lo deja en segundo plano. Compose crea la red, arranca MySQL y después la API. Recuerda que el .jar de target/ debe existir (paso 1 de la práctica 1).

2

Ver el estado y los logs

docker compose ps
docker compose logs -f api

Espera a que en el log aparezca Started SimpsonsApplication (si antes salen errores de conexión, es la API reintentando mientras MySQL arranca). Sal de los logs con Ctrl+C.

3

Probar la API

curl -X POST http://localhost:8080/api/v1/simpson \
  -H "Content-Type: application/json" \
  -d '{"name":"Marge Simpson","picUrl":"https://example.com/marge.png"}'

curl http://localhost:8080/api/v1/simpson

5.4 Parar la aplicación y qué pasa con los datos

Aquí los datos de MySQL viven dentro del contenedor. Veamos qué pasa según cómo lo pares:

4

Parar y volver a arrancar: los datos se conservan

docker compose stop
docker compose start
curl http://localhost:8080/api/v1/simpson

stop solo apaga los contenedores, no los borra: al arrancarlos de nuevo, Marge sigue ahí.

5

Bajar todo: los datos se pierden

docker compose down
docker compose up -d
curl http://localhost:8080/api/v1/simpson

down borra los contenedores y la red, y con ellos la base de datos. Al volver a levantar, MySQL empieza de cero y la lista sale vacía ([]). Recuerda esperar a que la API termine de arrancar antes de hacer el curl.

6

Cambiar el código y reconstruir solo la API

./mvnw clean package -DskipTests
docker compose up -d --build api

Primero se recompila el .jar (el Dockerfile solo lo copia) y después se reconstruye únicamente el servicio api.

Para que los datos sobrevivan a un down Habría que guardarlos fuera del contenedor con un volumen. En esta práctica no lo usamos para mantener el fichero lo más sencillo posible.
Si cambias la contraseña del .env MySQL guarda la contraseña al crear la base de datos. Si la cambias en el .env y vuelves a hacer up sin parar antes, la API dará Access denied. Haz primero docker compose down -v y levanta de nuevo.

6Comandos y resumen

Idea clave de la unidad Una imagen es la aplicación empaquetada y un contenedor es esa imagen en ejecución. El Dockerfile describe cómo construir la imagen y docker-compose.yml cómo se ejecutan juntos varios contenedores. La misma imagen funciona en tu ordenador y en cualquier servidor: solo cambia la configuración que le pasas.
